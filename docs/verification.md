# Verification

Run `npm run build` for strict UI/engine type checking and a reproducible bundle build. Run `npm test` for the current JavaScript and Python regression suite. `npm run test:browser` exercises the exact compiled bundle in isolated Chromium with physically muted output.

## Platform lanes

The `Verify` workflow runs build, JavaScript/Python regressions and all browser checks on `windows-latest`, `macos-latest` and `ubuntu-latest`. Each OS uploads its own receipts and browser evidence, including on failure. `.gitattributes` keeps embedded TypeScript source consistent across checkouts. These are platform-specific Chromium runs; they do not imply a Hermes native app or model was exercised.

Compose accepts 1–32 bars, eight layers and 2,048 notes. Regression coverage includes both meters, last-bar editing, shortened arrangements retaining later notes, persistence/import/undo, scheduling and wraparound beyond beat 16, and long WAV timing. The browser suite renders a real last-bar note and checks its onset in the exported PCM. A dense 2,048-note arrangement also plays, accepts a velocity edit and stops with the grid open. Grid hits are indexed by pitch and half-beat cell; velocity offsets are grouped in one pass. Clock-only updates retain the editor snapshot identity and update separate playhead/ruler/position components. Regression checks cover fractional and overlapping notes, bounded index work, and 1,000 clock-only ticks without an editor snapshot change. Existing 96 MiB canonical PCM and 192 MiB export-buffer budgets still apply; long, effect-heavy arrangements can require shorter tails or a narrower active loop.

## Real Desktop and model gate

`python scripts/native-desktop-proof.py --cdp-url http://127.0.0.1:9222 --allow-model` attaches to a **dedicated Hermes development/test instance** with a working configured model and this candidate plugin already installed and enabled. Install the dev requirements first. The command creates one hidden conversation and can incur normal model usage; its transcript remains in that test profile. Use a supported development build with loopback renderer CDP enabled, not a production app whose debugging interface is disabled. The test does not launch, install into, or reconfigure Hermes.

It rejects a browser harness, a non-Electron renderer, an ambiguous instance, and executing export or draft handlers whose module differs from `desktop/plugin.js` (except Hermes's import-URL rewrite). A matching but inactive parsed blob cannot establish provenance. It navigates through the actual route, checks the 32-bar control, requests Sound Draft through the native SDK, waits for a validated Fine tune candidate, observes the real create/submit/completion/cleanup calls, and compares valid live UI exports of all six assignments before and after generation, including unsaved in-memory state. It captures the generated JSON Blob instead of writing a file or clipboard, records the executing export module, and rejects a different draft-handler module before session creation. The forwarding observer never substitutes SDK or model responses. The candidate is discarded; failures attempt cancellation. Receipt JSON contains no prompt, reply, credentials or conversation identifiers. This test does not verify speakers or listening quality.

Missing prerequisites, backend/provider errors, malformed model output and cleanup failures fail the command. There is no skip or SDK-fixture fallback. `--allow-model` is mandatory, and the script accepts only loopback HTTP CDP URLs. It is separate from `npm test` and `test:browser` so ordinary checks cannot silently call a paid model.

The manually dispatched `Native Desktop and model` workflow runs the same gate on dedicated self-hosted runners labeled `sound-studio-native` plus `Windows`, `macOS` or `Linux`. Provision a test Desktop/model and set `HERMES_STUDIO_CDP_URL` in each runner's environment; install the exact checked-out candidate before dispatch. The source-match check prevents stale installed builds from yielding a green receipt. Runners are not provisioned by this repository. Do not attach these runners to untrusted pull-request workflows. Native coverage is established only after all three platform receipts pass; adding the workflow alone does not establish it.

Local validation for this change: Windows strict build, 277 JavaScript tests, 64 Python tests and 138 browser checks passed. Native execution remains unverified; the prerequisite-failure path and verifier guards have been exercised locally. Portable verifier regressions cover empty/unchanged storage, failed-save in-memory edits, stale parsed modules and forwarding the actual fixture lifecycle; those tests do not establish native/model acceptance. Linux/macOS CI and native receipts must be collected on their actual hosts before declaring cross-platform native acceptance.

## Existing coverage

Browser coverage includes control editing, four viewport sizes, note velocity, pan, loop bounds, export, reload, audio consent, playback position and real meters. Desktop-target checks compare played buffers against all six assigned patches with a maximum absolute sample tolerance of 1e-4 and RMS error of 1e-5, with a negative control requiring all six event references to remain distinguishable. A local fresh-build comparison measured approximately 3.04e-5 peak / 2.67e-6 RMS drift between canonical renders; exact sample equality is not assumed.

Sound Draft browser checks use a routed SDK fixture with isolated hidden conversations and recorded prompts; they never call an external model. They cover staying in Studio, progress, cancellation, completion after navigation, source-edit protection, feature-aware Fine tune tabs, immediate effect toggles, explicit audition/Stop/acceptance and invalid replies. Controller tests cover duplicate activation, exact route/socket ownership, cancellation during create, malformed replies, stale profiles, timeout without replay, SDK-supported create parameters, recovery of a lost create reply without resubmission, canonical admission cancellation and subscription detach, and legacy runtime close.

Playback geometry is compared before, during and after audition at 1440, 900 and 600 pixels. The timeline reserves its transport slot while idle; focusing Audition no longer expands helper copy or inserts an analysis row.

Audio-session browser checks leave and remount the production route, switch tasks and host sessions, launch Sound Draft, audition a returned patch, and mute each transport. They verify retained readiness/mute without autoplay or extra contexts, stopped playback on departure, closed contexts on plugin unload, and fresh consent after reload. Draft preview cleanup is checked against a real render with effect tails longer than six seconds.

Two quiet JSON regression fixtures are rendered through actual Web Audio. Browser checks verify the quiet warning, direct audition from audio-off, draft-only balancing, explicit acceptance, preserved notes/envelopes/effects and a measured peak around −18 dBFS. A silent fixture verifies actionable feedback without automatic amplification. Prompt calibration reduces compounded attenuation; model output still needs review.

The portable browser harness simulates the non-dialog Hermes SDK and Dialog host. It verifies the production plugin and actual Web Audio, not a running Hermes backend, external model provider, real speakers, OS volume or cross-browser audio equivalence. A native Windows run also completed one real background request using the configured gpt-6.1-sol model, displayed its validated Fine tune controls without navigation, and left the original assigned sound untouched. Native model verification is separate from the automated fixture and does not establish speaker/OS volume acceptance.

The release test list is explicit in `scripts/test-files.json`. It contains maintained domain, audio, persistence and generation regressions. Historical installation scripts, stale UI snapshots, delivery receipts and developer scratch fixtures are excluded from the release tree. No blanket claim that every historical development test passes is made.

Catalog admission is a separate check: `hermes plugins validate . --install-deps --json`. A passing local run is evidence for that tree and environment, not catalog acceptance. The catalog PR must pin the public repository's full 40-character commit SHA.

The 0.5.01 native security regressions cover approval directives for both file-writing tools, destination-scoped grants, host write-denylist enforcement, protected home/profile/install/plugin paths and resolved aliases, malformed apply arguments, and a real Node subprocess with a hostile parent NODE_OPTIONS preload. Run `python -B -m unittest discover -s tests -p test_security.py -v`; run the same suite with `hermes --run-module unittest discover -s tests -p test_security.py -v` to exercise the installed host policy. These tests do not grant live user approval or call a model.
